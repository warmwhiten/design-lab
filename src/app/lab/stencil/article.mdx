## 흰 부분이 주인공이다

실크스크린으로 찍은 포스터, 색연필로 칠한 스텐실 판 — 이런 그림에서 눈에 먼저 들어오는
클로버나 별이나 글자는 **칠해진 게 아니라 칠해지지 않은 곳**입니다. 판에 구멍을 뚫고
그 위로 잉크를 밀면, 구멍 난 자리에만 잉크가 안 올라가고 종이가 그대로 드러납니다.

이 순서를 뒤집으면 — 그러니까 배경을 칠하고 그 위에 흰 도형을 덮으면 — 아무리 질감을 잘 만들어도
경계에서 티가 납니다. 흰 도형에는 종이 결이 없고, 잉크의 번짐도 도형을 피해 가니까요.
그래서 이 도구는 실제 인쇄와 같은 순서로 갑니다.

```
종이  →  잉크 필드  →  마스크로 뚫기  →  질감
```

그리고 이 네 겹을 따로 그리지 않습니다. 픽셀 하나마다 네 값을 전부 구해서 한 번에 섞습니다.
덕분에 번짐이 마스크 경계를 넘나들고, 종이 섬유가 잉크를 뚫고 올라옵니다.

## 사진에서 실루엣 따기

사진을 흑백으로 바꾸면 밝기 배열이 하나 나옵니다. 여기서 "어디까지가 주제인가" 를 정하는 게
**임계값**인데, 이걸 사용자가 슬라이더로 처음부터 찾게 하면 도구를 열자마자 회색 뭉텅이만 봅니다.

그래서 기본값은 **오츠(Otsu) 알고리즘**이 정합니다. 히스토그램만 보고,
"여기서 자르면 앞과 뒤의 밝기가 가장 뚜렷하게 갈린다" 는 지점을 찾습니다.

```ts
for (let i = 0; i < 256; i++) {
  wB += hist[i];                    // 이 값 아래쪽 픽셀 수
  const wF = total - wB;            // 위쪽 픽셀 수
  const between = wB * wF * (mB - mF) ** 2;   // 두 무리가 갈린 정도
  if (between > best) { best = between; at = i; }
}
```

사진을 올리면 이 값이 자동으로 잡히고, `기준값` 슬라이더는 거기서 ±로 미세조정만 합니다.
그 뒤로 3×3 **다수결 필터**가 외톨이 점을 지우고 바늘구멍을 메우고
(연결요소 분석보다 훨씬 쌉니다), 블러 한 번에 좁은 계단 함수를 통과시키면
계단현상 없이 매끈한 경계가 나옵니다.

## "선만" 딸 때

`선` 모드는 임계값 대신 **소벨 필터**를 씁니다. 밝기가 급하게 변하는 곳이 곧 윤곽이라는 발상이고,
가로·세로 기울기를 각각 재서 그 크기를 씁니다.

```ts
const gx = (c + 2*f + r) - (a + 2*d + p);   // 가로 방향 변화
const gy = (p + 2*q + r) - (a + 2*b + c);   // 세로 방향 변화
out[i] = Math.hypot(gx, gy);
```

여기 나온 얇은 선을 원판으로 팽창시켜 굵기를 줍니다. 사진에 쓰면 내부 디테일까지 살아나서
라인 아트가 되고, 글씨에 쓰면 속이 빈 아웃라인 레터링이 됩니다.

**글씨는 이 파이프라인의 마지막 단계에 그냥 꽂습니다.** 캔버스에 그린 글자의 알파 채널이
이미 완벽한 이진 실루엣이라, 임계값만 건너뛰면 나머지 처리는 사진과 똑같이 흐릅니다.
사진용으로 만든 `경계 부드럽게`·`선 굵기`가 글씨에도 그대로 먹히는 이유입니다.

## 질감 세 가지

전부 해시 함수 하나에서 나옵니다. 격자 난수를 부드럽게 보간한 값 노이즈,
그걸 주파수를 배로 올려가며 겹친 fBm, 그리고 한 방향으로 길게 늘여 교차시킨 종이 섬유.

- **색연필** — 미세한 결로 잉크를 갉아먹고, 훨씬 낮은 주파수의 얼룩으로 "누르는 힘"을 흔듭니다.
  두 겹이 같이 있어야 손으로 칠한 느낌이 납니다. 하나만 쓰면 그냥 노이즈로 보입니다.
- **점묘** — 진짜 점을 찍습니다. 흔들린 격자마다 중심을 잡고, 그 자리 잉크 농도의
  제곱근에 비례하는 반지름으로 원을 그립니다. 기본값이면 1080px 판 하나에 십만 개 넘게 들어갑니다.
- **판화** — 경계를 좁은 계단으로 단단하게 만든 다음, 종이 섬유가 잉크를 뚫고 올라오게 합니다.
  `번짐`을 올리면 경계가 잉크 번지듯 일렁입니다.

### 점이 잘아지면 경계 처리가 전부다

점 하나가 두세 픽셀밖에 안 되면, 그 점이 원으로 보이느냐 각진 덩어리로 보이느냐는
경계를 어떻게 흐리느냐에 달립니다. 처음에는 흔한 방식대로 반지름에 비례하는 폭으로
부드러운 계단을 먹였는데, 점이 작아질수록 그 폭도 같이 줄어들어 안티에일리어싱이 무너졌습니다.
확대해 보면 점이 아니라 픽셀 블록이 흩어져 있었습니다.

고친 방식은 **원의 픽셀 덮임을 그대로 근사**하는 것입니다.

```ts
const c = (r - d) * 0.72 + 0.5;   // 반지름과 무관하게 항상 1.4px 폭
```

경계에서 픽셀이 원에 얼마나 걸쳐 있는지는 거리 `d`가 반지름 `r`을 지나는 정도에
거의 선형으로 비례합니다. 폭이 반지름과 무관하게 고정이므로 점이 아무리 잘아져도
가장자리가 부드럽고, 3배로 내보내면 점이 3배 커지면서 경계는 그대로 1픽셀이라
해상도가 올라간 만큼 또렷해집니다.

번짐은 잉크에 흐림을 주는 게 아니라 **마스크를 흔들어 읽는 것**입니다.

```ts
su += (fbm(x * bf, y * bf, seed + 61, 2) - 0.5) * bAmp;
sv += (fbm(x * bf, y * bf, seed + 73, 2) - 0.5) * bAmp;
m = sampleMask(mask, su, sv);
```

좌표를 노이즈로 밀어서 읽으면 도형의 경계가 손으로 오려낸 듯 일렁이고,
질감의 주파수만 바꿔도 같은 코드가 색연필의 부드러운 흔들림과 판화의 거친 이가 빠짐이 됩니다.

## 미리보기와 내보내기가 같은 그림인 이유

노이즈를 픽셀 좌표로 그대로 먹이면, 3배로 내보냈을 때 그레인만 1/3 크기로 작아집니다.
화면에서 고른 질감이 파일에서는 다른 질감이 되는 거죠.

그래서 모든 주파수를 **캔버스 짧은 변 기준**으로 정규화했습니다.

```ts
const U = Math.min(W, H);
const gf = 190 / C.gscale / U;      // 그레인
const dotSp = Math.max(2.2, U * C.dot);   // 점 간격
```

해시가 결정적이라 같은 좌표에는 언제나 같은 값이 나오고, 좌표를 `U`로 나눠 쓰니
1080px 미리보기와 3240px 내보내기가 픽셀 밀도만 다른 **같은 그림**이 됩니다.

## 격자는 마스크 한 장을 반복해서 읽는 것

9칸짜리 그림도 마스크는 한 장입니다. 픽셀이 몇 번째 칸에 속하는지 계산하고,
칸 안의 좌표로 바꿔서 같은 마스크를 읽습니다. `칸마다 흔들기`를 올리면
칸 번호를 해시에 넣어 회전·크기·팔레트 위치를 조금씩 어긋나게 합니다.

레퍼런스로 삼은 판화 포스터들은 아홉 칸이 전부 다른 그림이었지만,
사진 한 장에서 아홉 개의 다른 도형을 만들 수는 없습니다.
회전과 크기를 흔드는 게 여기서 할 수 있는 최선이고, 실제로 꽤 비슷해 보입니다.

## 안 되는 것

- **역광이나 배경이 복잡한 사진**은 실루엣이 안 나옵니다. 밝기만 보기 때문입니다.
  주제와 배경의 밝기가 갈리는 사진 — 제품컷, 나뭇잎, 인물 옆모습 — 이 잘 나옵니다.
- 결과물은 **픽셀**입니다. 질감이 픽셀 단위로 계산되므로 SVG로 내보낼 방법이 없습니다.
  인쇄용으로 쓴다면 3× (3240px) 로 뽑으면 A4 300dpi에 충분합니다.
- 올린 사진은 **브라우저 밖으로 나가지 않습니다.** 서버가 없는 정적 사이트라 그럴 수도 없습니다.

## 직접 만져볼 것들

- `잉크 필드`를 **단색 1도**로 두고 `잉크`를 **판화**로 바꾸면 실크스크린 포스터가 됩니다
- `번짐`을 0으로 내렸다가 1까지 올려 보세요. 같은 마스크가 인쇄기를 바꾼 것처럼 달라집니다
- 사진에서 실루엣이 안 잡히면 순서대로 — `기준값`을 좌우로 쓸어 보고, `안팎 뒤집기`를 켜 보고,
  그래도 지저분하면 `티끌 제거`를 올리세요
- 점묘에서 `점 간격`을 최소까지 내리면 점이 픽셀 두어 개 크기가 되면서 에어브러시처럼 풀립니다.
  개별 점을 보고 싶으면 0.008 근처까지 올리세요
- `씨앗`은 그레인과 별의 배치를 결정합니다. 다른 건 그대로 두고 이것만 돌려도 다른 인쇄가 됩니다
