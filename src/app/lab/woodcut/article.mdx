## 판화 글씨는 왜 판화처럼 보이나

리노컷이나 목판으로 찍은 글자를 보면 금방 알아봅니다. 그런데 무엇을 보고 알아보는 걸까요.
폰트가 특이해서가 아닙니다. 실제로 판화 알파벳의 뼈대는 대개 평범한 산세리프예요.
다른 건 **표면**입니다.

손으로 파고 잉크를 올려 종이에 누르는 과정에서 벌어지는 일들이 있습니다.

- 조각도로는 **직각을 팔 수 없다**. 모서리가 전부 둥글게 뭉개진다.
- 글자 속 구멍(카운터)은 파낸 자리다. 둥근 끌로 파면 **타원**이 된다.
- 손은 직선을 못 긋는다. 윤곽이 **느리게 흐느적거린다**.
- 칼날은 결을 만나면 튄다. 가장자리에 **잘게 거친 자국**이 남는다.
- 잉크는 번지고, 덜 묻는 자리는 **가장자리에 몰린다**.

이 도구는 이 다섯 가지를 각각 슬라이더로 만들었습니다.

## 핵심은 연산 하나

놀랍게도 위 목록의 앞 세 개는 **같은 연산 하나**에서 나옵니다.
글자를 흐리게 만든 다음, 어느 밝기를 기준으로 잘라내는 것.

```ts
const v = blurredAlpha[i];   // 흐려진 글자의 진하기 (0~1)
if (v > threshold) 잉크;      // 기준보다 진하면 잉크가 앉는다
```

블러를 먹인 뒤 자르면 뾰족한 모서리는 사라지고 둥글게 깎입니다.
가까이 있던 획끼리는 흐려지면서 서로 닿아 **매끈한 목으로 이어붙고**,
좁은 카운터는 사방에서 좁혀 들어와 **타원으로 줄어듭니다**.
조각도로 판을 팔 때 실제로 벌어지는 일과 결과가 같습니다.
그래서 이 도구에서 **블러 반경은 곧 조각도의 크기**입니다.

그리고 이 `threshold` 를 상수가 아니라 **자리마다 흔들리는 값**으로 바꾸면
나머지도 따라옵니다.

```ts
let t = 0.5 - 잉크량;
t += 손떨림 * (저주파노이즈(x, y) - 0.5);   // 느린 흔들림 = 손
t += 칼자국 * (고주파노이즈(x, y) - 0.5);   // 잘은 흔들림 = 칼날
```

큰 파도로 흔들면 손떨림, 잔물결로 흔들면 칼자국입니다.
기준선 자체를 올리고 내리면 잉크가 마르거나 번집니다.

## 잉크는 가장자리부터 빠진다

처음에는 잉크 결손을 글자 전체에 고르게 뿌렸습니다. 결과는 판화가 아니라 사포였어요.
실제 판화를 보면 **잉크는 안쪽에 꽉 차 있고 거친 것은 윤곽뿐**입니다.
판이 종이에 닿을 때 가장자리부터 힘이 빠지기 때문입니다.

그래서 결손 확률에 가장자리 가중치를 넣었습니다.
`v - threshold` 가 작다는 건 그 픽셀이 잉크 경계에 가깝다는 뜻이라,
이 값 하나로 "얼마나 가장자리인지"를 알 수 있습니다.

```ts
const edge = Math.max(0, 1 - (v - t) / 0.17);
const p = 결손 * (0.16 + 0.84 * edge);   // 안쪽 16%, 가장자리 100%
```

## 활자는 손으로 옮긴다

캔버스 위에서 글자를 직접 집어 끌 수 있습니다. Alt(또는 Shift)를 누른 채 좌우로 끌면 돌아갑니다.
집은 글자는 옆 패널에서 크기·기울기·회전을 숫자로 다듬을 수 있습니다.

이걸 자유 배치로 만들 수도 있었지만 그러지 않았습니다. 자유 배치로 가면
자간·줄간·크기 슬라이더가 손으로 옮긴 위치와 싸우게 되거든요. 슬라이더를 만질 때마다
공들여 잡은 배치가 무너지면 도구로서 최악입니다.

그래서 **자동 배치 위에 얹는 보정값**으로 만들었습니다. 슬라이더는 바탕 배치를 움직이고,
손으로 준 보정은 그 위에 그대로 얹혀 따라다닙니다. 활판 인쇄에서 조판된 활자를
하나씩 집어 살짝 옮기고 돌리는 것과 같습니다.

보정값은 글자 크기 대비 천분율로 저장돼서 주소창에 그대로 실립니다.
`nudge=1:126,-96,0` 은 *두 번째 글자를 오른쪽으로 126, 위로 96 옮겼다* 는 뜻이에요.
해상도와 무관한 단위라 1× 로 잡은 배치가 3× 로 내보내도 똑같이 나옵니다.

되돌리고 싶으면 **배치 되돌리기** 를 누르면 됩니다.

## 도형도 같은 판에 새겨진다

원·타원·직사각형·세모·별·다이아몬드·클로버·하트를 넣을 수 있습니다.
중요한 건 도형이 **글자와 똑같은 조각·잉킹을 거친다**는 점입니다.
따로 그려 붙이는 게 아니라 같은 판에 올라가서 같은 블러와 임계값을 받습니다.
그래서 도형 가장자리도 손으로 판 것처럼 흐느적거리고, 글자와 가까우면 잉크가 붙습니다.

각 도형은 안쪽 채움과 윤곽선을 따로 켜고 끌 수 있고 색과 선 두께도 정합니다.

## 색이 다르면 판을 따로 판다

여기서 문제가 하나 생깁니다. 판화는 원래 **판 하나에 잉크 한 색**입니다.
그럼 빨간 별과 검은 글자를 어떻게 같이 찍나.

실제 판화가 하는 그대로 했습니다. **색마다 판을 따로 파서 겹쳐 찍습니다.**
다색 목판화가 정확히 이 방식이에요.

결과가 물리적으로 맞아떨어집니다.

- **같은 색끼리는 한 판에 있으니 잉크가 번져 서로 붙습니다.**
  검은 글자 옆에 검은 도형을 붙이면 하나의 덩어리로 이어집니다.
- **다른 색은 다른 판이니 붙지 않고 그냥 겹칩니다.**
  빨간 별 위에 검은 글자가 올라가도 서로 뭉개지지 않습니다.

이게 규칙을 따로 만든 게 아니라 판을 나눈 결과로 저절로 나옵니다.
SVG 로 내보내면 판 하나가 경로 하나가 되어서, 벡터 편집기에서 색깔별로 집어 쓸 수 있습니다.

도형은 글자보다 아래에 깔립니다. 배지나 바탕으로 쓰는 경우가 많아서입니다.

## 같은 글자를 두 번 파면 다르게 나온다

판화의 성질 하나가 더 있습니다. 같은 단어를 두 번 새기면 절대 같지 않다는 것.
**다시 새기기** 버튼이 그겁니다. 시드만 바뀌고 나머지 설정은 그대로예요.
마음에 드는 판이 나오면 링크를 복사해 두면 시드까지 주소에 들어가서
나중에 같은 판이 그대로 다시 나옵니다.

## SVG 는 '판', PNG 는 '찍힌 종이'

내보내기가 둘로 나뉘어 있습니다.

**SVG** 는 조각면만 담습니다. 잉크 결손은 빠져요.
결손까지 벡터로 옮기면 튄 점 하나마다 경로가 하나씩 생겨서
경로 수천 개짜리 파일이 되거든요. 로고나 실크스크린 출력용 원본으로 쓸 것이라
깨끗한 조각면이 맞습니다.

**PNG** 는 종이에 찍힌 상태 그대로입니다. 잉크 결손도 종이결도 다 들어갑니다.

## 어디에 쓰나

로컬 브랜드 로고, 진(zine)이나 포스터 제목, 앨범 커버, 굿즈 레터링처럼
**손맛이 필요하지만 실제로 판을 팔 수는 없는** 자리에 씁니다.

시작은 헤비 산세리프가 가장 좋습니다. 조각과 잉크가 이미 개성을 만들기 때문에
원본 폰트는 담백할수록 결과가 좋아요. 장식적인 폰트로 시작하면 개성이 두 번 겹쳐서
지저분해집니다. 갖고 있는 폰트를 올려서 써도 됩니다.
